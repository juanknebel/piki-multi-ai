# Persistent sessions (headless session daemon)

Design + implementation plan for tmux-style session persistence: every PTY
tab (shell, agent, lazygit) survives closing the TUI, closing the desktop app,
a crash, or an ssh drop, and is re-attached on the next start with its screen
and scrollback intact.

This is option **B** from the 2026-08-21 assessment ("own daemon"), chosen over
a hidden tmux backend (tmux swallows the OSC 133/7/777 sequences piki's agent
status relies on and forces alt-screen scrolling) and over zellij/dtach/abduco.
The design follows [shpool](https://github.com/shell-pool/shpool) (Google's
"tmux without the UI"): a headless daemon owns the PTYs and a terminal
emulator per session; thin clients attach over a Unix socket and receive a
restore buffer generated from the emulator state. Where piki differs from
shpool it is called out below.

`docs/performance.md` §4 already identified this as "headless client/server
architecture — a feature, not perf". This document is the design.

## Goals / non-goals

Goals:

- A tab's process keeps running when the frontend (TUI or desktop) exits,
  crashes, or loses its terminal. Reopening the frontend shows the same tabs,
  same screen, same scrollback, same agent status.
- Zero external runtime dependency (no tmux). Same binaries as today.
- Both frontends share sessions (they already share SQLite): a tab opened in
  the TUI is visible in the desktop and vice versa.
- Agent status (cli-agent FIFO, OSC 133/7/777, passive Codex detection) keeps
  working, including for events that happen while nobody is attached.
- Closing a tab still kills its process (explicit intent). Quitting the app
  detaches by default and asks when there are live sessions.
- Graceful degradation: if the daemon cannot start or is incompatible, the
  frontend falls back to today's in-process PTY (`Local` backend) with a
  toast, never a dead app.

Non-goals (for now):

- Remote (ssh) sessions, multi-user, systemd socket activation.
- Persisting non-PTY tabs' *content* (Kanban/API Explorer state). Their
  presence in the tab bar is restored; state is not.
- Surviving a daemon crash: the daemon holds the PTY masters, so daemon death
  means SIGHUP for every child — same blast radius as a tmux server. The
  daemon is kept tiny and boring for that reason.

## Architecture

```
 ┌───────────────────────┐      ┌───────────────────────┐
 │ piki-multi-ai (TUI)   │      │ piki-desktop (Tauri)  │
 │  Tab.pty_session ─────┼──┐   │  DesktopTab.pty ──────┼──┐
 │  (PtySession::Remote) │  │   │  (RawPtySession::Remote) │
 └───────────────────────┘  │   └───────────────────────┘  │
          unix socket  <data_dir>/sessions/daemon.sock        │
 ┌──────────────────────────────────────────────────────────┴──┐
 │ session daemon   (`piki-multi-ai serve` / `piki-desktop --serve-sessions`)
 │  Server { sessions: HashMap<SessionId, Session> }            │
 │  Session { child, master, writer, vt100::Parser (restore),   │
 │            OscParser + ShellSession (status), FIFO reader,   │
 │            clients: Vec<ClientSink>, meta, exit }            │
 │  reader thread per session: master → parser → fan-out        │
 └──────────────────────────────────────────────────────────────┘
```

Key decisions (and how they differ from shpool):

| Topic | shpool | piki |
|---|---|---|
| Daemon binary | separate `shpool daemon` | same binaries, `serve` subcommand (TUI) / `--serve-sessions` flag (desktop); `piki_core::session::daemon::run` |
| Discovery / autostart | client autodaemonizes `shpool daemon` | identical: `ensure_daemon(paths)` spawns `current_exe()` detached and polls the socket (≤5 s, exponential backoff) |
| Socket | `$XDG_RUNTIME_DIR/shpool/shpool.socket` | always `<data_dir>/sessions/daemon.sock` (alongside lock+pid) so `--data-dir` instances are isolated; an overflowing path is addressed at the `bind`/`connect` syscall via the `session::uds` proxy, never by relocating the file |
| Session identity | user-chosen name | uuid v4 generated by the client at spawn; equals the tab id |
| Attach policy | one client, `Busy` otherwise | N clients (fan-out); resize = latest attach/resize wins |
| Restore | screen only (`contents_formatted` + input modes), optional last-N-lines | screen **+ scrollback** (vendored vt100 gains `Screen::history_formatted()`), + input modes |
| Terminal emulation | `shpool_vt100` fork | the already-vendored `vt100` 0.16 (same lineage) |
| Exited sessions | removed when the shell exits | retained (final screen + exit code) until the frontend removes them or a 1 h reaper runs; that is how a dead tab still shows its last output after a restart |
| Shell integration | prompt sentinel + motd | OSC 133/7/777 parsed **in the daemon**; state snapshot + event stream forwarded to clients; FIFO for Claude hooks owned by the daemon |
| Daemon lifetime | forever | exits after 60 s with no sessions and no clients |
| Encoding | msgpack | JSON for control messages, raw bytes for data frames — no new deps |
| Peer check | SO_PEERCRED uid + exe | SO_PEERCRED / LOCAL_PEERCRED uid only |
| Fallback | none | `Local` backend (today's code path) when the daemon is unavailable, incompatible, or disabled in config |

## Wire protocol (`piki_core::session::protocol`)

Transport: Unix stream socket, mode 0600, directory 0700. Every frame is

```
[kind: u8][len: u32 little-endian][payload: len bytes]
```

Frames with binary payload: `Input`, `Output`, `Restore`. Every other payload
is a JSON document (serde). The protocol version is an integer constant
`PROTOCOL_VERSION`; bump it on any incompatible change.

Connection handshake:

1. daemon → client: `Hello { protocol, version, pid }` (one frame).
2. client → daemon: exactly one `Request`:

| Request | Reply | Notes |
|---|---|---|
| `Ping` | `Pong` | presence probe |
| `List` | `Sessions(Vec<SessionInfo>)` | live + exited sessions with meta |
| `Spawn(SpawnRequest)` | `Spawned { info }` / `Error` | creates a session; when `attach: true` the connection becomes an attach stream right after the reply |
| `Attach { id, rows, cols }` | `Attached { info, shell }` / `Error` | connection becomes an attach stream |
| `Kill { id }` | `Ok` / `Error` | SIGHUP, then SIGKILL after 500 ms; session stays as *exited* |
| `Remove { id }` | `Ok` / `Error` | drop an exited session (kills first if live) |
| `SetMeta { id, title?, order?, workspace_path? }` | `Ok` / `Error` | frontends push tab metadata here; the daemon is the source of truth for PTY tabs |
| `Shutdown { force }` | `Ok` / `Error` | refuses when live sessions exist and `force == false`; used for protocol upgrades |

`SpawnRequest { id, command, args, cwd, env: Vec<(String,String)>, rows, cols,
integration_on, cli_agent_sock: Option<PathBuf>, meta: SessionMeta, attach }`.
The client sends the **complete** child environment (TUI: its own env +
`LaunchPlan.env`; desktop: `user_login_env()` + TERM/COLORTERM + plan env)
and the daemon `env_clear()`s before applying it — spawn results are
identical regardless of which binary started the daemon.

`SessionMeta { workspace_path, provider (label / Custom name), title:
Option<String>, order: u32, closable: bool, created_at_unix_ms }`.
`SessionInfo = meta + id + cwd + command + args + state (Live{attached:
usize} | Exited{code: Option<i32>}) + started/exited timestamps`.

Attach stream frames:

| Direction | Frame | Payload |
|---|---|---|
| C→D | `Input` | raw bytes for the PTY |
| C→D | `Resize { rows, cols }` | JSON |
| C→D | `Resync` | re-send `Restore` at the current size (desktop uses it when xterm mounts) |
| C→D | `Detach` | close politely (EOF also detaches) |
| C→D | `Kill` | same as the control request |
| D→C | `Restore` | `ESC c`-style reset + screen + scrollback + input modes; sent right after `Attached` and on `Resync` |
| D→C | `Output` | live PTY bytes |
| D→C | `ShellState(snapshot)` | full shell/agent state; sent after `Attached` |
| D→C | `ShellEvent { event, replayed }` | one `ShellEvent`; `replayed == true` for events buffered while nobody was attached (badges yes, OS toast no) |
| D→C | `Exited { code }` | child exited (also delivered on attach to an exited session) |
| D→C | `Heartbeat` | every 5 s; a failed write drops the client sink |
| D→C | `Detached { reason }` | daemon is dropping this client (kill/remove/shutdown) |

Terminal queries (DSR/DA) are answered by the **daemon's** parser so agents
that probe the terminal at startup get replies even when nobody is attached;
the client-side parser's answerback is discarded.

Back-pressure: each client sink is a bounded channel (256 frames) drained by
its own writer task; a full channel drops that client (logged). The PTY
reader thread never blocks on a client.

## Daemon internals (`piki_core::session::daemon`)

- `run(paths, foreground)` — entry for the binaries. Unless `foreground`, it
  double-forks + `setsid` + redirects stdio to `/dev/null` (shpool
  `daemonize.rs`), takes an exclusive `flock` on `<sessions>/daemon.lock`
  (second instance exits 0), writes `daemon.pid`, logs to
  `<data_dir>/logs/sessions.log`, removes a stale socket (connect →
  `ECONNREFUSED`), binds, then `serve`s on a tokio runtime.
- `serve(listener, ctx)` — accept loop; one task per connection; all errors
  are per-connection (the accept loop never dies).
- `Session` — built from `SpawnRequest` with the same `portable-pty` code as
  today's `PtySession` (moved into `session::pty`). Reader thread
  (`spawn_blocking`): `read → parser.process (+ answerback to master) →
  OscParser.feed → ShellSession apply → fan-out Output + ShellEvent frames`.
  On EOF: `try_wait` for the exit code, broadcast `Exited`, mark the session
  exited, keep it.
- Restore = `parser.screen().state_formatted()` preceded by a reset and the
  scrollback (`history_formatted()`), generated after resizing the daemon
  parser to the attaching client's size.
- Events while detached: ring of the last 64 `ShellEvent`s, flushed on attach
  with `replayed: true`.
- Reaper task (60 s cadence): drops exited sessions older than 1 h, and exits
  the daemon after 60 s of zero sessions + zero clients.
- Signals: `SIGTERM`/`SIGINT` → unlink socket + pid file, exit. (Children get
  SIGHUP when the masters close — inherent.)
- Peer check on every connection: uid must equal the daemon's.

## Client side (`piki_core::session::client`)

- `ensure_daemon(paths) -> Result<DaemonHandle, DaemonError>`; `DaemonError::
  Incompatible { daemon_protocol, live_sessions }` when the protocol differs
  and live sessions exist (callers fall back to `Local` + toast); when no
  live sessions exist the client sends `Shutdown` and respawns from its own
  binary.
- `Control` — one short-lived connection per request (`list`, `spawn`,
  `kill`, `remove`, `set_meta`, `shutdown`, `ping`), sync `std::os::unix::net`
  with read timeouts; callers in async contexts wrap it in `spawn_blocking`.
- `Attachment` — the long-lived stream: a sync writer handle (`Input`,
  `Resize`, `Resync`, `Detach`, `Kill`) and a blocking reader loop that
  delivers frames to a callback.

### `PtySession` facade (core) and `RawPtySession` (desktop)

`PtySession` keeps its public API (`write`, `parser`, `bytes_processed`,
`resize`, `kill`, `is_alive`, `peek_alive`, `shell`, `abort_reader`) and
becomes an enum-backed facade:

- `Local` — today's implementation, unchanged (tests, fallback,
  `[sessions] enabled = false`).
- `Remote` — an `Attachment`: the reader loop feeds the client-side
  `vt100::Parser` with `Restore`/`Output` bytes, mirrors `ShellState`/
  `ShellEvent` frames into the client-side `ShellSession`, raises
  `PtyOutputSignal`, and flips `exited` on `Exited`/EOF. `kill()` sends
  `Kill`; `abort_reader()`/`Drop` send `Detach` (never kill).

The desktop's `RawPtySession` grows the same `Remote` variant; its reader
emits the same Tauri events as today (`pty-output`, `pty-exit`,
`pty-shell-event`, `pty-agent-event`).

## Frontend integration

### TUI

- `main.rs`: parse the CLI before starting tokio; `serve [--foreground]`
  runs the daemon; everything else enters the runtime as today.
- `helpers::spawn_tab`: `ensure_daemon` (once per process, cached) →
  `Control::spawn(attach: true)` → `PtySession::Remote`. Fallback to
  `Local` on any daemon error, with a toast.
- Startup: `Control::list()`; for every live/exited session whose
  `workspace_path` matches a workspace, create the tab (order from meta) and
  attach. Sessions with no matching workspace are left running and listed in
  the sessions dialog (never killed silently).
- Non-PTY tabs (Kanban/API/markdown) and the active tab index are restored
  from a per-workspace UI pref (`tui_tabs:<path>`), written on every tab
  change; PTY entries in it are reconciled against the daemon list (a PTY
  entry whose session is gone becomes a *dead* tab with a restart hint).
- `shutdown()` detaches. The existing quit confirm becomes: *N sessions keep
  running in the background — [Enter] quit, [k] quit and kill all, [Esc]*.
  `[sessions] on_quit = "ask" | "detach" | "kill"` in `config.toml`.
- Dead tab: `Enter` restarts it with the same provider (`ProviderConfig.
  resume_args`, e.g. `["--continue"]` for Claude, appended on restart only);
  `prefix x` removes it (`Remove`).
- Tab rename/reorder → `SetMeta`.
- New CLI: `piki-multi-ai serve [--foreground]`, `piki-multi-ai sessions
  list|kill <id>|stop`.

### Desktop

- `main.rs`: `--serve-sessions [--data-dir X]` handled before Tauri (like
  `--printenv`).
- `spawn_tab`/`spawn_editor_tab`/`spawn_terminal_at`/`dispatch_agent` →
  daemon spawn with `attach: true`.
- Setup: list sessions and populate `DesktopWorkspace.tabs` before the
  frontend loads; the existing `wsTabsV2` layout restore then reconciles by
  content id (ids are stable now).
- Frontend: on `createTerminal` send `ipc.resyncPty(tabId)` so the restore
  lands in a mounted xterm (output for unmounted tabs is dropped today and
  must stay cheap). `close_tab` kills; window close detaches; menu entry
  *Quit and kill all sessions*.

## Persistence model

The daemon is the source of truth for PTY tabs (meta lives in the session).
SQLite only stores the lightweight per-workspace layout pref (non-PTY tabs,
order, active tab). No schema migration is needed.

Reconciliation on startup (both frontends):

| Layout entry | Daemon session | Result |
|---|---|---|
| PTY, present | live | attach |
| PTY, present | exited | dead tab with final screen + exit code |
| PTY, present | missing | dead tab, "not running — Enter to restart" |
| absent | live/exited, workspace matches | adopt (append, ordered by meta) |
| absent | live/exited, no workspace | left alone; visible in the sessions dialog |
| non-PTY | — | recreated empty (Kanban/API); CodeReview/markdown skipped |

## Lifecycle semantics

| User action | Today | With the daemon |
|---|---|---|
| Close tab (`prefix x`) | kill | kill (+ `Remove`) |
| Delete/remove workspace | kill its tabs | kill + remove its sessions |
| Quit (`prefix q`) | kill everything | detach (ask when live sessions exist) |
| Crash / terminal closed | everything dies | sessions survive; next start re-attaches |
| Process exits | tab shows exited | same; the final screen survives a restart |

## Security

- Socket 0600 in a 0700 directory under the user's data dir.
- Peer uid check on every connection (`SO_PEERCRED` on Linux, `getpeereid`
  on macOS).
- The daemon only ever runs what a same-uid client asks it to — it has no
  more authority than the client.
- FIFOs for cli-agent hooks stay 0600 under `<data_dir>/claude-hooks/sock/`,
  named by session id, unlinked when the session is removed.

## Failure modes

| Failure | Behaviour |
|---|---|
| Daemon not running | autostart; if the socket never comes up (5 s) → `Local` fallback + toast |
| Daemon protocol mismatch, no live sessions | `Shutdown` + respawn from the client's binary |
| Daemon protocol mismatch, live sessions | `Local` fallback + toast explaining how to upgrade (`piki-multi-ai sessions stop`) |
| Daemon dies while attached | reader EOF → tab marked dead ("session daemon exited"); all children got SIGHUP |
| Client dies / wedged | heartbeat write fails or channel fills → sink dropped; session keeps running |
| Two clients attached | both receive output; last resize wins |
| Socket path too long | socket stays in the data dir; `session::uds` addresses it via a short proxy at the syscall — daemon `chdir`+bind (single-threaded), client dials `/proc/self/fd/<dirfd>/daemon.sock` on Linux (no cwd change) / mutex-guarded `chdir` elsewhere |
| Stale socket file | `ECONNREFUSED` → unlink before bind |

## Testing strategy

- Protocol: frame round-trips, JSON compat (`#[serde(default)]` on every
  struct field so additive changes don't break older peers).
- vt100 restore: feed N>rows lines + attributes into parser A; generate
  restore; feed into fresh parser B; assert `contents()` at every scrollback
  offset match (property-style over random lines).
- Daemon integration (`crates/core/tests/session_daemon.rs`): in-process
  `serve` on a temp socket (no fork): spawn `cat`, attach, write, read,
  detach, re-attach → restore contains the echoed text; two attachments;
  kill → `Exited`; list; remove; reaper; shutdown refusal.
- Client facade: `PtySession::Remote` against the in-process daemon with the
  same assertions as `tests/pty_session.rs`.
- TUI: dialog handler tests (quit choices, dead-tab restart), snapshot for the
  quit dialog, reconciliation unit tests with a fake session list.
- CI parity: `just ci` before every commit (`cargo fmt`, clippy `-D warnings`
  on the workspace minus desktop, tests, frontend `tsc && vite build`).

## Phases

Each phase ends green on `just ci` and is committed on `persistence-sessions`.

1. **Foundations (core)** — `session::protocol` (types, framing, tests),
   `DataPaths::sessions_dir/session_socket`, vt100 `history_formatted` +
   round-trip tests, serde on `ShellEvent`/`CliAgentEvent`, `ShellState`
   snapshot ⇄ `ShellTabState`, `launch_plan` takes the session id for a
   stable FIFO path, `uuid` dep in core.
2. **Daemon** — `session::daemon` (server, session, reader, fan-out,
   restore, FIFO, reaper, signals, lock, logging) + integration tests.
3. **Client + facade** — `session::client` (`ensure_daemon`, `Control`,
   `Attachment`, daemonize spawn), `PtySession::{Local,Remote}`, tests.
4. **TUI** — `serve`/`sessions` subcommands, spawn through the daemon,
   startup reconciliation, quit dialog, dead-tab restart, `SetMeta` sync,
   `[sessions]` config, catalog/README/config.example parity.
5. **Desktop** — `--serve-sessions`, `RawPtySession::Remote`, startup
   attach, `resync` on mount, close/quit semantics, frontend build green.
6. **Polish** — sessions dialog (TUI) + `sessions` CLI, replayed-event
   badges, docs (README Persistence/Architecture, AGENTS.md,
   performance.md §4 closure), final QA pass.

Status: all six phases shipped. The TUI sessions overlay (`prefix ctrl-s`)
landed after the initial cut, and `[sessions] enabled` is honored by both
frontends (desktop via `session::sessions_enabled()`). Still open from the
phase-6 list: replayed-event badges (the `replayed` flag exists on the wire,
unused). The desktop Sessions dialog (Alt+Shift+S) shipped after, and now has Adopt
(`adopt_session`: same `tab_from_session` path as startup re-attach), a
startup restore toast + per-workspace `↺` badge (`restore_summary`), a
`sessions N / off / unavailable` status-bar segment (`session_status`, the
list call as liveness probe, polled every 3s) and a quit dialog that counts
daemon-backed vs in-process tabs (`quit_summary`). Closing a running tab in
the desktop asks Close / Keep running / Cancel — *Keep running* is
`detach_tab`: the window drops its attachment (Drop sends `Detach`, never
`Kill`, and no `remove_session`), so the session lives on as detached.
