# piki-desktop

Tauri v2 desktop GUI for piki-multi. **Depends on `piki-core`, `piki-api-client`, and `piki-agent`.**

## Architecture

- `src/main.rs` — Tauri entry point, setup, command registration.
- `src/state.rs` — `DesktopApp`, `DesktopWorkspace`, `DesktopTab { custom_title: Option<String> }` + `TabInfo { custom_title }` with `display_label()`/`getTabLabel(tab, termTitle?)` (`custom_title` > terminal OSC title (frontend only, `TabShellState.title`) > `provider.label()`, 40-char cap) and `rename_tab` Tauri command; state structs managed by Tauri. `TabInfo.custom_title` is set via `rename_tab` (workspace_idx + tab_id + Option<title>) and mirrored in `frontend/src/state.ts:renameTab()` + `frontend/src/types.ts:getTabLabel()`.
- `src/pty_raw.rs` — `RawPtySession`: streams raw PTY bytes to frontend via Tauri events (no `vt100`).
- `src/events.rs` — Tauri event emission helpers (sysinfo, git refresh, toast).
- `src/commands/session.rs` — persistent-session daemon commands: `list_sessions`/`kill_session`/`remove_session` (Sessions dialog; jump uses `local_workspace_idx`/`local_tab_idx`, `workspace_idx` is the loaded workspace matching the session's path), `adopt_session(session_id, workspace_idx) -> tab_idx` (attach + `session::tab_from_session`, the same builder startup re-attach uses — keep them identical), `session_status` (async, `spawn_blocking`; `on`/`off`/`unavailable` + live count from `DesktopApp.sessions_enabled` + the daemon, plus `enabled_next` = `app_settings::resolve` re-read each poll so the bar appends `(restart)` when Settings changed it — the status bar polls it every 3s), `restore_summary` (what `session::reattach_sessions` restored, stored on `DesktopApp.restore_summary`, read once by `main.ts` for the toast + `appState.markRestored` badge) and `quit_summary` (alive tabs split by `pty.is_remote()`, drives the quit dialog wording). Frontend: `dialogs/sessions-dialog.ts`, opened by `Alt+Shift+S` / View menu / palette / the `sessions N` status-bar segment. `sessions_available` (daemon present?) is read once at startup into `appState.sessionsAvailable` and gates the "Keep running" option; `commands/pty.rs::detach_tab` implements it — removes the tab so `RawPtySession::Remote`'s Drop sends `Detach` (never `Kill`, never `remove_session`), and refuses for a local (in-process) tab.
- `src/commands/` — Tauri IPC commands: `workspace.rs`, `pty.rs`, `git.rs` (phase 08 added `git_pull` — aborts a conflicting pull and names the files, passes a diverged refusal through —, `git_amend(message: Option)`, `git_last_commit_message`, `git_discard_file(path, untracked)` — `restore --worktree` vs `clean -fd`, the flag is the caller's explicit choice —, `git_list_branches(include_remotes)` and `git_checkout_branch(branch, remote)` — never `-f`, git's refusal is the error; parsing/summary helpers live in `piki_core::git` with unit tests: `parse_branch_list`, `parse_ahead_behind`, `pull_summary`, `BRANCH_LIST_FORMAT`), `system.rs`, `chat.rs` (includes `chat_send_agent_message` for agentic tool-use, `chat_set_agent_mode`/`chat_get_agent_mode`), `lsp.rs` (LSP server lifecycle commands). `pty.rs::move_tab(from_workspace_idx, tab_id, to_workspace_idx) -> new_idx` re-parents a `DesktopTab` between workspaces WITHOUT dropping it (no Detach/Kill; the frontend's xterm stays bound to the same tab id) and re-points a daemon session's `workspace_path` via `Daemon::set_meta` off-lock. `workspace.rs::delete_workspace` kills the workspace's tabs and removes their daemon sessions before the worktree goes (a plain drop would only detach them) — the delete confirm promises exactly that.
- `src/commands/system.rs::open_url(url)` — the ONE way to open a URL in the browser (terminal links: Ctrl+click via `@xterm/addon-web-links`, the terminal menu's *Open Link*); http(s) only, refused otherwise, through `tauri_plugin_shell::ShellExt` (`#[allow(deprecated)]` — migrate to `tauri-plugin-opener` app-wide, not per call site). Frontend: `ipc.openExternalUrl`. Never `window.open` inside the webview. `src/commands/clipboard.rs` (`wl-copy`/`xclip`/`pbcopy` spawns) is only the FALLBACK: `ipc.clipboardCopy`/`clipboardPaste` go through `@tauri-apps/plugin-clipboard-manager` first and fall back when the plugin errors.
- `src/commands/search.rs` — `fuzzy_file_list` returns `piki_core::search::FileIndex { files, truncated }` (workspace-relative, sorted). **Per-workspace cache pattern:** the result is memoised on `DesktopWorkspace.file_index: Option<Arc<FileIndex>>`; the command reads the cache under the lock, walks off-lock in `spawn_blocking` (`piki_core::search::list_files`, `ignore::WalkBuilder` — `.gitignore`/`.ignore`/global excludes, hidden kept, `.git` pruned, `FILE_INDEX_CAP` = 50k) and stores it only if the workspace at that index still has the same path. Invalidation lives where the change is observed: `events::spawn_git_watcher` clears it when the drained watcher events are anything but content edits of files already in the index (`FileIndex::contains`), `workspace.rs::switch_workspace` clears it on switch. Reuse this shape for any other derived-from-disk list: cache on the workspace struct, fill off-lock, invalidate from the watcher drain. Frontend: `components/fuzzy-search.ts` renders before the IPC resolves (last list per workspace path shown meanwhile, `Indexing…` in the `.palette-footer`), `Enter`/click → editor tab (`registerCodeFile`/`registerMarkdownFile` + `appState.addTab`, same as `file-tree.ts` `openFile`), `Alt+Enter` → read-only viewer, `Ctrl+E` → `$EDITOR`; `file-kind.ts` (`looksBinary`, `isMarkdownPath`, pure, vitest) decides which files never get an editor tab.
- `src/lsp/` — LSP WebSocket proxy: `registry.rs` (server config from `lsp.toml`), `server.rs` (`LspManager` with TTL idle shutdown, max concurrent cap), `proxy.rs` (WebSocket server bridging JSON-RPC to child processes). `LspManager` uses `tokio::sync::Mutex` (not `parking_lot`) for async server spawn operations.
- `frontend/` — Vanilla TypeScript + xterm.js + CodeMirror 6 web frontend, built with Vite. Frontend-only tab types (Markdown, CodeEditor, WebPreview) use synthesized tab ids (e.g. `web-${Date.now()}`) and `appState.addTab` without calling `ipc.spawnTab`; their close handlers in `tab-bar.ts` skip `ipc.closeTab` and destroy local state directly. Any tab/pane close must go through `tearDownAndCloseWsTab` / `tearDownAndClosePane` (tab-bar.ts, both async): dirty-editor prompt, then a `showConfirm` naming every live PTY process (`liveProcessLine`, agent status included) with Close / Keep running (`ipc.detachTab`, offered only when `appState.sessionsAvailable`) / Cancel, then `releasePtyContents` (highest index first; a tab that fails to release stays open) + `destroyTerminal` + panel teardown — never call `appState.closePane`/`closeWsTab`/`ipc.closeTab` directly from UI code, and never `.catch(() => {})` a close/rename (use `reportError`). `markTabDead` (on `pty-exit`) emits `tabs-changed` + `pane-tree-changed` so the `.ws-tab--dead` chip, the pane-head `↻ Restart` button (`restartPaneContent`: `ipc.closeTab` the exited tab → `ipc.spawnTab` same provider → `appState.replacePaneContent` into the same pane, custom title carried over) and the status bar's `(exited)` all update immediately. Shell integration: `pty_raw.rs` runs an `OscParser` on shell-tab byte streams and emits `pty-shell-event` Tauri events (cwd, command exit codes); the frontend listens in `main.ts` and updates `appState.applyShellEvent` so the status bar shows cwd and the tab bar shows ✓/✗ badges. Provider-tab idle watcher polls in `events::spawn_idle_watcher_loop` and emits `pty-attention` events that mark workspace badges. **Agent attention flow:** `pty_raw.rs::handle_cli_agent` emits `pty-agent-event { status, kind, summary, attention }` per tab; `attention` is true for permission / idle-notification / stop until the user looks at the tab. Acks are backend-owned — `events::acknowledge_agent_attention(tab)` clears the marker and returns whether it did, `events::emit_agent_ack` sends `pty-agent-ack { tab_id }` (always after the `DesktopApp` lock is dropped); `set_active_tab` / `switch_workspace` call both, and `handle_cli_agent` acks on the spot when the event lands on the active tab of the active workspace (TUI semantics: seen as it lands — that event goes out with `attention: false`). Frontend: `appState.applyAgentEvent` / `applyAgentAck` keep `TabShellState.attention`; always pass it as the 2nd arg of `cliAgentStatusView` (tab bar, status bar, close-confirm line, Agents panel). `appState.agentRows` (+ `agentRowsFetchedAt`, event `agent-rows-changed`) is the ONE store for `list_agent_rows` — `startAgentRowsSync()` in `agents-panel.ts` (called once from main.ts) does the debounced fetch and `setAgentRows` also seeds per-tab shell state so a daemon-restored tab shows its dot; never fetch rows from a component. Consumers: Agents panel, `workspace-list.ts` rollup, `status-bar.ts` `● N need you` segment, `activity-bar.ts` amber badge on the Explorer icon, and `jumpToAttention()` (`Alt+A`, palette, Agents menu) which uses the pure `agent-attention.ts` (`attentionRows`, `pickAttentionTarget` — severity order + cyclic walk —, `liveElapsedSecs`; vitest-covered). `AgentRow.elapsed_secs` comes from `CliAgentState::run_started_at`; `formatElapsed` (`types.ts`) mirrors `piki_core::cli_agent::format_elapsed` and the panel ticks the label in place every second. Agents panel: `agents-panel.ts`, docked at the bottom of `#sidebar` below the switchable views wrapper `#sidebar-views` — ALWAYS visible no matter which view (Explorer/Files/Source Control) is active (not a switchable view itself; the activity-bar "agents" icon opens the profile-manager dialog), height resizable via the `#agents-resize-h` drag handle in `sidebar.ts` (clamped 32px–75% of the sidebar, persisted as `settings.agentsPanelHeight`), lists live agent tabs across ALL workspaces (`label` is `DesktopTab::display_label()` so a renamed tab shows its custom title); rows are a keyboard `listbox` (Tab into it, ↑/↓/Home/End move, Enter/click jump via `jumpToAgentRow`; focus survives re-renders by `data-tab-id`). The workspace list (`workspace-list.ts`) renders a per-row agent rollup glyph — collapsed worktree families aggregate hidden children by `family_key`/`source_repo` — using `types.ts::agentStatusSeverity`/`actionableStatusView` (mirrors of `piki_core::cli_agent::status_severity` and the TUI's `actionable_status_view`); its ⚙ opens `showAgentManager(idx)` for THAT row's workspace. `dialogs/needs-workspace.ts` `showNeedsWorkspace(why)` is the empty state for agent profiles / dispatch with zero workspaces (CTA → create). `main.rs` resolves the shared settings at startup — `piki_core::app_settings::resolve(config_path, storage.ui_prefs)` (Settings ▸ General override in the DB > `[sessions]`/`[notifications]` in `config.toml` > default) — then `effective.notifications.apply()` (so `delivery = "off"` silences the desktop like the TUI) and `connect_session_daemon(&paths, effective.sessions_enabled)`; the value it started with is `DesktopApp.sessions_enabled`. `menu-bar.ts` `preloadProviderTabs()` warms the File ▸ New Tab provider list at init (and after `invalidateProviderCache`). **Tab bar / sidebar / switcher (phase 07):** `tab-bar.ts` renders a scrolling `.ws-tab-strip` with the `+` and the `⋯` "all tabs" button (`allTabsMenuItems` → `openContextMenu`) outside it; middle-click (`auxclick` button 1) and the tab context menu (`wsTabMenuItems`: Rename / Split / Move to workspace… / Close / Close keep running) all go through `tearDownAndCloseWsTab(wsIdx, i, { mode? })` — `mode: "detach"` skips the confirm for the menu's "keep running". `moveWsTabToWorkspace(wsIdx, wsTabIdx)` (also `moveActiveWsTabToWorkspace()` for menu bar + palette) is the ONLY move path: `createDropdown` inside `showConfirm` picks the target, `ipc.moveTab` per content (PTY contents only — editors/boards refuse), then `appState.moveWsTab` re-homes the pane tree and flushes the layout snapshot synchronously before the switch. `dialogs/delete-workspace.ts` `confirmDeleteWorkspace(idx)` is the ONE delete confirm (sidebar menu + palette): wording by `workspace_type`, `ws.changedFiles.length`, live agents from `appState.agentRows`. `workspace-list.ts` rows have a single `⋯` + right-click → `workspaceMenuItems(idx)`. `workspace-switcher.ts` ranks with the pure `mru.ts` (`mruBump`/`mruRank`/`rankItems`, vitest) over the `workspaceMru` settings list that `appState.setActiveWorkspace` bumps (the single choke point for switches); rows show `statusGlyph` (agent rollup or dirty git). `labels.ts` `branchLabel()`/`truncateMiddle()` is the one branch-label rule (28 chars, middle ellipsis, full text in `title`) — use it wherever a branch renders. `provider-cache.ts` (`preloadProviderTabs`/`getCachedProviderTabs`/`invalidateProviderCache`, re-exported by menu-bar) is the shared providers.toml list for every "open here" chooser; `pane-view.ts` `renderEmptyState()` is the per-workspace empty state (name · branch + Shell / providers / Open file…) used for both a tab-less workspace and a blank pane — `renderWelcome` is only for "no workspace at all". `sidebar.ts` `maxAgentsPanelHeight()` clamps the Agents panel so ≥4 workspace rows stay visible. Chevrons: one SVG path (`▸`), rotated 90° when expanded — never add a new glyph. Tab renaming: top bar `tab-bar.ts` `wsTabTitle()` uses `getTabLabel()` and triggers `beginInlineRename()` on dblclick (context menu → Rename) (the label becomes an `.ws-tab-rename` input — Enter commits, Esc cancels, blur commits, empty clears; targets the ACTIVE pane's content via `activeContentId(wt)`; `renderWorkspaceTabBar` skips a refresh while the input exists so agent-status ticks don't wipe it; `appState.renameTab()` + `ipc.renameTab()`); status bar and dashboard also use `getTabLabel()`. Keyboard shortcuts: `shortcuts.ts` is the single registry (rebindable defs with `category` + non-rebindable `fixedShortcuts`); the help dialog derives from `helpSections()` and the menu bar, palette, welcome screen and tooltips read keys via `getShortcutKey` — never hardcode a key string anywhere. **The terminal owns its keys:** a def is outside-only by default (skipped while `focusOwnsKeys()` — xterm, `<input>`/`<textarea>`, contenteditable editors — is true); it captures everywhere only with `terminalCapture: true`, which the `ShortcutDef` union restricts to a `TerminalSafeCombo` default (`Alt+…`, `Ctrl+Shift+…`, `Ctrl+Alt+…`) — `tsc` fails on `{ defaultKey: "Ctrl+B", terminalCapture: true }`. At runtime `isTerminalSafeCombo(def.key)` re-applies the rule to user rebinds. `fixedShortcuts` rows must be keys that really fire somewhere (copy/paste are platform-aware there), and `RESERVED_COMBOS` blocks rebinding onto them. `Alt+1…9` (workspace N) and `Ctrl+Tab` are dispatched from `handleGlobalKeydown` via `switch-workspace`/`switch-tab` DOM events handled in `main.ts`.

```bash
cd crates/desktop/frontend && npm install && cd -

```

## Conventions

- `settings.ts` / `settings-store.ts` — the ONLY way to read or write the `settings` JSON document. `await settingsStore.load()` runs first in `main.ts`; afterwards `settingsStore.get(key)` is synchronous and `settingsStore.patch(key, value)` (or `undefined` to delete) schedules one debounced full-document write. Never call `ipc.getSettings`/`ipc.setSettings` from a component — the old per-caller read-modify-write raced (a sidebar drag could drop a pending pane-layout flush). Keep the store IPC-free (`settings-store.ts` takes a `SettingsBackend`; `settings.ts` binds it to Tauri) so it stays unit-testable.
- Stylesheets: `styles/index.css` is the single import (from `main.ts`) and its `@import` order is the cascade — add a new sheet there, never as a `<link>` in `index.html`. Foundation order is `fonts` → `variables.css` → `reset.css` → `primitives.css` → `motion.css`, then the shell and feature sheets. The dialog family is split: `dialog-core.css` (backdrop, `.dialog` size budget, body/field/label, footer, `.dialog-dropdown-*`, badges, the `showConfirm` overlay) followed by `dialog-providers.css`, `dialog-agent.css`, `dialog-logs.css`, `dialog-help.css`, `dialog-workspace.css`, `dialog-git.css`, `toast.css`, `file-viewer.css`, `dialog-settings.css` — a new dialog's own rules go in a new `dialog-<feature>.css` imported in that group. All `@keyframes` live in `styles/motion.css` (also the global `prefers-reduced-motion` block); feature CSS only references animation names (`overlay-in`, `dialog-enter`, `menu-enter`, `toast-in`, `pulse`, …). `src/css-invariants.test.ts` (vitest, reads the sheets with `node:fs` — typed by `src/test-node-shim.d.ts`) fails on: `outline: none` outside a `:focus-visible` rule that paints a replacement, a `z-index` that is not a `--z-*` token, a colour literal outside `variables.css`, `transition: all`, a sheet missing from `index.css`. `tauri-plugin-window-state` (Rust side, `main.rs`) restores size/position/maximized/fullscreen.
- **UI primitives** (`styles/primitives.css`, token-built, modifiers wrapped in `:where()` so a feature rule of equal specificity always wins). Add the primitive class next to the feature's own hook class and keep only feature-specific modifiers in feature CSS; never re-declare a button/input/surface from scratch.
  - `.ui-surface` — floating shell (bg, border, radius, `--shadow-lg`, flex column, `dialog-enter`). The caller owns the size:
    ```html
    <div class="dialog ui-surface">…</div>          <!-- .dialog = width/max-height only -->
    <div class="palette ui-surface">…</div>          <!-- also .diff-viewer, .kanban-edit-modal, .ws-delete-dialog -->
    ```
  - `.ui-header` — title row (`min-height: var(--header-height)`, `--bg-surface`, bottom border) with `.ui-header-title` (ellipsis) and an optional `.ui-header-actions` slot (right-aligned, never shrinks):
    ```html
    <div class="ui-header"><span class="ui-header-title">Sessions</span>
      <div class="ui-header-actions"><button data-variant="secondary" data-size="sm" class="ui-btn">Refresh</button>
      <button data-variant="ghost" data-icon class="dialog-close ui-btn" title="Close" aria-label="Close">×</button></div></div>
    ```
  - `.ui-btn` — `data-variant="primary|secondary|ghost|danger"`, `data-size="sm|md"` (md = `--control-height` 30px, sm = `--control-height-sm` 22px), `data-icon` (square glyph button, sm unless `data-size="md"`), `.active` (toggle on: secondary fills accent, ghost turns accent), `:disabled`, `[aria-busy="true"]` (pulses). Focus ring is an outset outline so it shows on a primary fill. From TS: `btn.className = "ui-btn"; btn.dataset.variant = "primary"; btn.dataset.size = "sm"` (`dataset.icon = ""` for `data-icon`).
    ```html
    <button data-variant="primary" class="ui-btn">Create</button>
    <button data-variant="secondary" data-size="sm" class="ui-btn ag-edit">Edit</button>
    <button data-variant="ghost" data-icon class="ws-action-btn ui-btn" title="Workspace menu">⋯</button>
    ```
  - `.ui-input` — `<input>` / `<textarea>`: same height as `.ui-btn` (`--control-height`; `data-size="sm"` = `--control-height-sm`), `--bg-input`, accent border + `--focus-ring` halo on `:focus-visible` (the only sanctioned `outline: none`), `[aria-invalid="true"]` red border + `--focus-ring-error`, `[readonly]`/`:disabled` dimmed. A textarea grows from 2× the control height and resizes vertically. `.dialog-dropdown-trigger` (`createDropdown`) shares the height, so inputs, dropdowns and the path-picker button line up in one row.
    ```html
    <input class="ui-input" id="ws-name" placeholder="auto-derived if empty" />
    <input data-size="sm" class="kanban-search-input ui-input" type="text" />   <!-- feature CSS: width only -->
    <textarea class="ui-input" id="ws-prompt" rows="3"></textarea>
    ```
  - `.ui-empty` — centered muted block: `.ui-empty-icon`, `.ui-empty-title`, `.ui-empty-hint`, `.ui-empty-cta` (a `.ui-btn`), `data-fill` (take the whole pane), `data-tone="error|loading"`. Every "No X" / "Loading…" / "Failed to …" message is one of these — no bespoke empty classes.
    ```html
    <div class="ui-empty">No stashes</div>
    <div class="ui-empty" data-fill data-tone="error"><span class="ui-empty-icon">B</span>
      <p class="ui-empty-title">Could not load kanban board</p><p class="ui-empty-hint">${err}</p></div>
    ```
  - **Keyboard focus is visible everywhere**: `reset.css` paints `--focus-ring-width` of `--accent-focus` as an inset outline on any `:focus-visible` element (rows, tabs, chrome buttons, checkboxes); `.ui-btn` moves it outside the button; text fields use the border + halo; full-pane editors (`.api-editor`, `.file-viewer-textarea`, the markdown `.ProseMirror`) use `--focus-ring-inset`. Writing `outline: none` anywhere else fails `src/css-invariants.test.ts`. Not migrated on purpose (chrome, not controls): `.pane-btn`, `.ws-tab-close/-add/-more`, `.wc-btn`, `.mk-toolbar-btn`, `.chat-code-copy`, `.kanban-color-swatch`, menu/activity/status bars — they get the global ring.
  - **How to add a dialog**: `backdrop.className = "dialog-backdrop <family>-backdrop"`; `dialog.className = "dialog ui-surface"` (+ a `.<family>-dialog` width class in `dialog-<family>.css` if 560px is wrong); `.ui-header` with `.ui-header-title` + `.dialog-close ui-btn` (ghost, `data-icon`); `.dialog-body` of `.dialog-field` (`.dialog-label` + `.ui-input` / `createDropdown()` / `attachPathPicker`); `.dialog-footer` with secondary Cancel first, primary action last; destructive flows go through `showConfirm` instead. Escape/Enter and the close button wire up as in `dialogs/stash-dialog.ts`; the feature's own rules go in `styles/dialog-<family>.css` imported after `dialog-core.css`.
- Frontend unit tests: vitest, `src/**/*.test.ts`, `npm test` (node environment, no DOM). Test pure modules (registries, scoring, stores); DOM-bound components are exercised in the Rust/E2E layers.
- Shared frontend primitives — use these, never re-implement them:
  - `components/confirm.ts` `showConfirm()` — every destructive/confirm overlay (renders `.ws-delete-confirm` markup with Escape/Enter, focus trap, safe-button initial focus, focus restore). Never hand-roll a confirm overlay.
  - `components/toast.ts` `reportError(context, err)` — every user-initiated failure path (error toast + console.error). A bare `console.error` is only acceptable for background/polling failures.
  - `components/a11y.ts` `makeInteractive(el, role?)` — any clickable `div` row/tab (tabindex + role + Enter/Space). Keyboard focus styling comes from the global `:focus-visible` rule in `styles/reset.css` (see UI primitives below for buttons / text fields).
  - `components/fuzzy.ts` — `fuzzyScore`/`fuzzyScorePath` + `mruBump`/`mruRank` for palette-style overlays (command palette and fuzzy file search already use them).
  - `in-flight.ts` `runExclusive(key, fn)` / `isInFlight(key)` / `onInFlightChange(cb)` — the one-op-at-a-time guard for any user-triggered async action that must not run twice (push, pull, checkout): while `fn` is pending under `key` every other call resolves to `undefined` without running (the caller toasts "… already in progress"), a rejection releases the key. Pure, vitest-covered. A panel re-renders its busy buttons from `onInFlightChange` + `isInFlight` (Source Control header: disabled + `↑…`).
  - `components/git-actions.ts` `pushWorkspace(wsIdx)` / `pullWorkspace(wsIdx)` / `confirmDiscardFile(wsIdx, file, onDone)` / `refreshGitStatus(wsIdx)` — the ONE implementation of push / pull / discard used by the panel, the Git menu and the palette (guard keys `pushKey(wsIdx)` / `pullKey(wsIdx)`, status refresh, toasts, `reportError`). Never call `ipc.gitPush`/`ipc.gitPull` from UI code directly. `source-control.ts` `focusCommitBox({ amend? })` is the entry point for "Commit" / "Amend Last Commit" (module-level `amendMode` survives the panel's full re-renders). `dialogs/branch-picker.ts` `openBranchPicker()` is the branch switcher (palette-style overlay, `fuzzyScore`, `git-checkout:<ws>` guard; `switch-branch` shortcut, status-bar branch click, Git menu, palette).
  - `components/context-menu.ts` `openContextMenu(x, y, items)` — every right-click / "…" menu (viewport-clamped, Esc / click-outside / blur close, Arrow/Home/End/Tab focus movement, focus restore; `CtxItem { label, action, danger, disabled, separator }`, styles in `styles/context-menu.css`). The file tree uses it; tabs/workspaces/terminal menus must too.
  - `components/dropdown.ts` `createDropdown(options, initial)` — the only select: `.dialog-dropdown-trigger` is sized like `.ui-input`, the list is `--z-popover`, items have `.highlight` (keyboard) and `:focus-visible`.
- Dialog backdrops are scoped per family: `backdrop.className = "dialog-backdrop <family>-backdrop"` and open() removes only `.<family>-backdrop` — removing bare `.dialog-backdrop` destroys unrelated open dialogs.
- No raw palette hex in feature CSS: use `variables.css` tokens, including the semantic aliases `--success-color`/`--error-color`/`--warning-color` and `--on-accent` (text over accent backgrounds).
- **CSS tokens** (`styles/variables.css` is the token layer; feature CSS never repeats a literal font, size, z-index or duration):
  - Fonts: `--font-mono` is the ONLY place the `"JetBrainsMono NF Mono"` name appears in `styles/` (the `@font-face` blocks live next to the `.ttf` files in `src/fonts/fonts.css`, imported first from `index.css`); `--font-ui` is the chrome face (aliases mono today). TS that must hand a literal to a non-CSS consumer reads it with `cssToken("--font-mono", fallback)` from `theme.ts` (xterm in `terminal-panel.ts`); inline `style=` strings use `font-family:var(--font-mono)`.
  - Type scale: `--font-size-base` (12.5px, `html`) and `--fs-3xs…--fs-4xl` (7/9/10/11/12/12.5/13/14/16/18/20px) + `--fs-display-sm/--fs-display/--fs-display-lg` (28/32/48px). Line heights `--leading-none/tight/normal/relaxed/loose` (1/1.4/1.5/1.6/1.75). Spacing `--sp-1…6` (2/4/6/8/12/16px — used for `gap`; paddings still literal). Radii `--radius-xs/sm/md/lg/full` (2/4/6/10/99px).
